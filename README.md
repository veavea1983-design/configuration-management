# Эмулятор командной оболочки UNIX

Практическая работа №1 по дисциплине «Конфигурационное управление»

**Вариант:** 3  
**Язык программирования:** Python 3  
**Реализованы этапы:** 1 — REPL, 2 — Конфигурация, 3 — VFS, 4 — Основные команды, 5 — Дополнительные команды
## 1. Описание проекта

Программа представляет собой эмулятор командной оболочки UNIX-подобной операционной системы.

На первом этапе реализован интерактивный консольный интерфейс (CLI), позволяющий вводить команды, обрабатывать аргументы и получать результаты выполнения.

Программа использует реальные данные операционной системы для формирования приглашения к вводу.

## 2. Реализованные функции

| Функция | Описание |
|---|---|
| `get_prompt()` | Формирует приглашение к вводу на основе имени пользователя и компьютера |
| `expand_variables()` | Раскрывает переменные окружения вида `$NAME` |
| `execute_command()` | Разбирает введённую строку и обрабатывает команды |
| `main()` | Запускает интерактивный цикл ввода команд |

### Поддерживаемые команды

| Команда | Описание |
|---|---|
| `ls` | Выводит имя команды и переданные аргументы |
| `cd` | Выводит имя команды и переданные аргументы |
| `exit` | Завершает работу эмулятора |

На первом этапе команды `ls` и `cd` являются заглушками. Работа с файловой системой будет реализована на следующих этапах.

Дополнительно предусмотрены обработка неизвестных команд, проверка аргументов команды `exit` и поддержка пустого ввода.

### Настройки

На первом этапе отдельный конфигурационный файл и параметры командной строки не предусмотрены.

Имя пользователя, имя компьютера и переменные окружения получаются из текущей операционной системы.

## 6. Примеры использования

Пример работы эмулятора:

```text
user@hostname:~$ ls
ls: аргументы = []

user@hostname:~$ ls folder1 folder2
ls: аргументы = ['folder1', 'folder2']

user@hostname:~$ cd documents
cd: аргументы = ['documents']

user@hostname:~$ hello
hello: команда не найдена

user@hostname:~$ exit wrong
exit: неверные аргументы

user@hostname:~$ exit
```

При запуске имена пользователя и компьютера подставляются автоматически.

Пример раскрытия переменной окружения Windows:

```text
user@hostname:~$ ls $USERNAME
ls: аргументы = ['user']
```

Значение переменной зависит от настроек операционной системы.

## 7. Этапы разработки

- **Этап 1. REPL** — консольный интерфейс, обработка команд и переменных окружения.
- **Этап 2. Конфигурация** — параметры запуска и конфигурационный файл JSON.
- **Этап 3. VFS** — виртуальная файловая система.
- **Этап 4. Основные команды** — реализация команд `ls`, `cd`, `clear`, `uname`, `tree`.

Работа выполняется последовательно, с сохранением изменений в истории Git-коммитов.

## 8. Этап 2 — Конфигурация

На втором этапе реализована поддержка параметров командной
строки, JSON-конфигурации и автоматического выполнения
стартовых скриптов.

### Параметры командной строки

| Параметр | Назначение |
|---|---|
| `--vfs` | Путь к виртуальной файловой системе |
| `--startup-script` | Путь к стартовому скрипту |
| `--config` | Путь к конфигурационному JSON-файлу |

Пример запуска с параметрами:

```bash
py src/main.py --vfs data/vfs --startup-script scripts/startup.txt
```

Пример запуска с конфигурационным файлом:

```bash
py src/main.py --config config.json
```

### Конфигурационный файл

Файл `config.json` содержит параметры:

- `vfs_path` — путь к виртуальной файловой системе.
- `startup_script` — путь к стартовому скрипту.

Пример содержимого:

```json
{
  "vfs_path": "data/vfs",
  "startup_script": "scripts/startup.txt"
}
```

Значения из JSON-файла имеют приоритет над соответствующими
параметрами командной строки.

На втором этапе путь к VFS принимается как настройка,
но сама виртуальная файловая система ещё не загружается.

### Стартовые скрипты

Стартовый скрипт содержит команды эмулятора,
по одной в каждой строке.

При выполнении отображаются введённые команды
и результаты их обработки.

При обнаружении неизвестной команды или неверных
аргументов выполнение скрипта прекращается.

Команда `exit` штатно завершает работу эмулятора.

### Функции второго этапа

| Функция | Описание |
|---|---|
| `process_command()` | Обработка команды с возвратом статусов |
| `parse_arguments()` | Чтение параметров запуска |
| `load_config()` | Загрузка конфигурации из JSON |
| `get_settings()` | Применение приоритета настроек |
| `print_settings()` | Отладочный вывод настроек |
| `run_startup_script()` | Выполнение стартового скрипта |
| `interactive_mode()` | Интерактивный режим эмулятора |

Доработанные функции первого этапа:

- `execute_command()` — использует новую обработку команд.
- `main()` — поддерживает конфигурацию и стартовые скрипты.

### Скрипты проверки

Для тестирования второго этапа созданы BAT-скрипты:

| Файл | Назначение |
|---|---|
| `scripts/test_cli.bat` | Проверка аргументов командной строки |
| `scripts/test_config.bat` | Проверка приоритета JSON |
| `scripts/test_error.bat` | Проверка остановки при ошибке |

### Автоматическое тестирование

Для запуска всех тестов из корневой папки проекта
используется команда:

```bash

```

Тестовый набор содержит:

- 6 тестов второго этапа.

Всего — 13 автоматических проверок.

### Примеры использования

Запуск с настройками из JSON:

```bash
py src/main.py --config config.json
```

Запуск с указанием стартового скрипта:

```bash
py src/main.py --startup-script scripts/startup.txt
```

## 9. Этап 3 — Виртуальная файловая система

На третьем этапе реализована загрузка виртуальной
файловой системы (VFS) из директории пользователя.

Все данные загружаются в оперативную память.
Исходные файлы и директории не изменяются.

### Источник VFS

Источником VFS является обычная директория на диске.

Пример запуска:

```bash
py src/main.py --vfs data/vfs_small
```

Загрузка VFS включает:

- Чтение структуры вложенных директорий.
- Загрузку содержимого файлов в память.
- Поддержку двоичных данных.
- Проверку существования исходной директории.
- Обработку ошибок загрузки.

### Реализованные функции

| Функция | Описание |
|---|---|
| `VirtualFileSystem.__init__()` | Создание объекта VFS |
| `VirtualFileSystem.load()` | Загрузка VFS в память |
| `VirtualFileSystem.save()` | Сохранение VFS на диск |
| `VirtualFileSystem.get_info()` | Информация о VFS |
| `load_vfs()` | Подключение VFS к эмулятору |
| `save_vfs_command()` | Обработка команды сохранения |

На третьем этапе доработаны функции:

- `process_command()`
- `execute_command()`
- `run_startup_script()`
- `interactive_mode()`
- `main()`

### Команда vfs-save

Команда сохраняет текущее состояние VFS
в указанную директорию.

Синтаксис:

```text
vfs-save путь
```

Пример:

```text
vfs-save output/saved_vfs
```

Папка назначения должна отсутствовать
или быть пустой.

Запрещено сохранять VFS поверх исходной директории
или внутрь неё.

### Тестовые файловые системы

Для проверки подготовлены следующие VFS:

| Директория | Назначение |
|---|---|
| `data/vfs` | Основная VFS |
| `data/vfs_minimal` | Минимальная VFS |
| `data/vfs_small` | VFS с несколькими файлами |
| `data/vfs_deep` | VFS с глубокой вложенностью |

### Скрипты проверки

Для тестирования используются:

- `scripts/test_vfs_minimal.bat`
- `scripts/test_vfs_small.bat`
- `scripts/test_vfs_deep.bat`
- `scripts/startup_vfs.txt`
- `scripts/startup_vfs_error.txt`

### Запуск автоматических тестов


## 10. Этап 4 — Основные команды UNIX

На четвёртом этапе реализована работа основных команд
с виртуальной файловой системой.

Программа поддерживает навигацию по каталогам,
просмотр содержимого директорий и вывод дерева файлов.

### Реализованные команды

| Команда | Назначение |
|---|---|
| `ls` | Просмотр текущего каталога |
| `ls путь` | Просмотр указанного каталога |
| `cd путь` | Переход в каталог |
| `cd ..` | Переход к родительскому каталогу |
| `cd /` | Переход в корень VFS |
| `clear` | Очистка экрана терминала |
| `uname` | Вывод названия операционной системы |
| `tree` | Вывод дерева файлов и каталогов |
| `tree путь` | Вывод дерева указанного каталога |

### Навигация по VFS

Команды работают с виртуальной файловой системой,
загруженной в оперативную память.

Поддерживаются:

- Абсолютные пути, например `/home/user`.
- Относительные пути, например `home/user`.
- Переход к родительскому каталогу через `..`.
- Обращение к текущему каталогу через `.`.
- Возврат в корень через `/`.

Переходы между виртуальными каталогами
не изменяют текущую директорию реальной ОС.

### Примеры использования

Запуск эмулятора:

```bash
py src/main.py --vfs data/vfs_deep
```

Пример работы:

```text
$ ls
home/

$ cd home
$ ls
user/

$ cd user
$ ls
docs/
notes.txt

$ cd ..
$ tree
user/
├── docs/
│   └── readme.txt
└── notes.txt
```

Команда `uname` выводит название реальной ОС.

Команда `clear` очищает экран терминала
с помощью управляющих ANSI-последовательностей.

### Добавленные функции

| Функция | Назначение |

| `require_directory()` | Проверка каталога |
| `change_directory()` | Изменение текущего каталога |
| `list_directory()` | Получение содержимого |
| `get_current_path()` | Текущий виртуальный путь |
| `build_tree_lines()` | Построение дерева каталогов |
| `render_tree()` | Формирование дерева файлов |
| `ls_command()` | Выполнение ls |
| `cd_command()` | Выполнение cd |

## 11. Этап 5 — Дополнительные команды UNIX

На пятом этапе реализованы команды `touch` и `rm`
для создания и удаления файлов в виртуальной
файловой системе.

Все изменения выполняются в оперативной памяти.
Исходные файлы и каталоги не изменяются.

### Команда touch

Команда создаёт пустой файл в виртуальной
файловой системе, если его ещё нет.

Синтаксис:

```text
touch имя_файла
```

Пример:

```text
touch example.txt
```

Если файл уже существует, его содержимое
остаётся без изменений.

Если родительский каталог отсутствует,
программа сообщает об ошибке.

Создание файла с именем существующей
директории запрещено.

### Команда rm

Команда удаляет файл из виртуальной
файловой системы.

Синтаксис:

```text
rm имя_файла
```

Пример:

```text
rm example.txt
```

Если файл отсутствует, программа сообщает
об ошибке.

Удаление директорий не поддерживается.

### Работа с виртуальными путями

Обе команды используют механизм путей,
реализованный на четвёртом этапе.

Поддерживаются:

- Пути относительно текущего каталога.
- Абсолютные виртуальные пути.
- Обозначения `.` и `..`.
- Работа с файлами во вложенных каталогах.

### Сохранение изменений

Создание и удаление файлов не изменяет
исходную директорию на диске.

Для сохранения текущего состояния используется
команда третьего этапа:

```text
vfs-save output/final_vfs
```

Состояние VFS сохраняется в отдельную директорию.

### Новые функции

| Функция | Назначение |
|---|---|
| `touch_file()` | Создание пустого файла в памяти |
| `remove_file()` | Удаление файла из памяти |
| `touch_command()` | Обработчик команды touch |
| `rm_command()` | Обработчик команды rm |

На пятом этапе также доработана функция
`run_shell_command()`.
